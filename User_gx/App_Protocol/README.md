# 视觉模块与 STM32 USART2 协议 v2

USART2使用115200、8N1接收下文的二进制视觉协议。已撤销临时串口舵机切换功能，裸字符`1`及视觉帧中的`0x31`不会直接触发舵机；中断只组帧入队，执行器由任务逻辑控制。KEY2选择蓝方启动，KEY3选择红方启动。

相机/香橙派只负责图像采集、检测和上报。STM32 负责选目标、跨帧关联、搜索、转向、接近、转运和舵机控制。协议接收代码只更新场景缓存，不会直接控制执行器，也不运行电机闭环。任务状态机应在 STM32 本地业务层实现。

USART2：115200 baud、8N1、3.3 V TTL，共地。STM32 PD5 为 TX、PD6 为 RX。传输原始二进制字节，不是 ASCII 十六进制字符串。

串口1使用PA9作为TX，115200、8N1、文本接收。已删除周期性的相机接收统计和图像摘要，保留任务状态`[TASK]`、转向事件`[TURN]`日志，以及连续10秒未收到任何字节时单次打印的`uart_error`。收到任意字节（不要求解析成功）后重新计时；上电从接收启动时计时。`rescue_usart2.h`中的`RESCUE_DEBUG_ENABLE`仅控制超时提示，任务日志由`APP_TASK_DEBUG_ENABLE`控制。说明见`App_Task/README.md`的“串口1任务日志与接收超时”；视觉接收和协议保持原样。

## 1. 通用帧与兼容性

```text
AA 55 | VER | CMD | SEQ | LEN | PAYLOAD... | CRC_LO CRC_HI | 0D 0A
```

| 字段 | 字节数 | 定义 |
|---|---:|---|
| 帧头 | 2 | `AA 55` |
| VER | 1 | `02`；v1 帧会被解析器拒绝 |
| CMD | 1 | 消息类型，见下表 |
| SEQ | 1 | 发送端每发一帧递增，255 后回绕到 0；不是目标 ID |
| LEN | 1 | 载荷长度，本版最多 244 字节 |
| PAYLOAD | LEN | 所有多字节整数采用小端序 |
| CRC | 2 | CRC-16/CCITT-FALSE，低字节先发 |
| 帧尾 | 2 | `0D 0A` |

最大帧长 254 字节；原有 `CMD=10` 最大仍为224字节。按 LEN 定位帧尾，载荷中可以包含 `AA 55` 或 `0D 0A`。

CRC 参数：初值 `FFFF`、多项式 `1021`、不反射、最终异或为 0。覆盖范围从 VER 到 PAYLOAD 末尾，不含帧头、CRC 和帧尾。

| CMD | 方向 | LEN | 用途 |
|---:|---|---:|---|
| `05` | 相机 -> STM32 | 0 | 心跳；只说明串口服务在线 |
| `10` | 相机 -> STM32 | `14 + 10*N` | 一幅图像的完整检测列表，N=0～20 |
| `11` | 相机 -> STM32 | `16 + 12*N` | 可选扩展检测列表，含采集至发送耗时及跟踪ID，N=0～19 |
| `20` | STM32 -> 相机 | 4 | 视角上下文：`view_id:uint16, yaw:int16` |

v1 的轮速、偏航角、舵机、停车和 ACK 消息已移除；即便把旧动作命令的版本改成 02，它们也不会触发执行器。v2 数据流不逐帧 ACK、不重发旧图像，损坏或丢失的帧由后续新图像替代。相机按采集顺序发送，使用单个发送队列，禁止旧推理任务完成后覆盖新图像。

本次保留版本02及原0x10字节布局，新固件同时接收0x10/0x11。旧固件不支持0x11，启用扩展前须更新STM32。相机继续发送0x10时不需要修改原有编码调用。

## 2. 检测列表 `CMD=10`

### 图像头，14 字节

以下偏移均相对于 PAYLOAD 起点。

| 偏移 | 字节数 | 字段 | 定义 |
|---:|---:|---|---|
| 0 | 2 | frame_id | 图像编号，每幅新图像递增，65535 后回绕；空场景也递增 |
| 2 | 4 | capture_ms | 相机单调时钟的图像采集时间，uint32 毫秒 |
| 6 | 2 | view_id | 采集时生效的视角编号，0 表示尚未设置 |
| 8 | 2 | image_width | 检测坐标对应图像宽度，像素，必须 >0 |
| 10 | 2 | image_height | 检测坐标对应图像高度，像素，必须 >0 |
| 12 | 1 | flags | bit0=图像及检测有效；bit1=检测列表被截断；其余必须为 0 |
| 13 | 1 | object_count | 本帧条目数 N，0～20 |

必须每幅图像发送完整列表，不是“只发送新出现的物块”。上次有目标、本次没有目标时也必须发帧，否则 STM32 无法区分空场景与相机断流。

- `flags=01, N=0`：成功采集和检测，本帧没有检测到目标；覆盖旧列表。
- `flags=00, N=0`：采集/推理失败；立刻使场景不可用。宽高仍填写当前配置值。
- `flags=03`：图像有效，但列表不完整；未出现在列表中的目标不能据此判定消失。
- 图像无效时禁止携带目标或设置截断标志。

每帧最多 20 个检测条目，包含物块、安全区等。超过 20 时相机必须设置截断标志；发送保留条目时优先覆盖危险物块、障碍和对方车，再按固定顺序填充其他检测。截断场景不能作为“路线没有障碍”的证明，STM32 应采用保守的停止/重新观测策略。如果实际任务频繁超过上限，需要另行设计分包或更长长度字段，不能直接把 40 条装进当前帧。

### 每个检测条目，10 字节

第 i 个条目从 `14 + 10*i` 开始，i=0～N-1。

| 条目内偏移 | 字节数 | 字段 | 定义 |
|---:|---:|---|---|
| 0 | 1 | type | 物体类型，见下表 |
| 1 | 1 | confidence | 置信度 0～100，百分数；不是颜色原始阈值 |
| 2 | 2 | cx | 检测框中心 x，像素 |
| 4 | 2 | cy | 检测框中心 y，像素 |
| 6 | 2 | width | 检测框宽度，像素，必须 >0 |
| 8 | 2 | height | 检测框高度，像素，必须 >0 |

坐标原点为图像左上角，x 向右，y 向下。相机须将裁剪、缩放、letterbox 等模型坐标还原到所上报宽高对应的图像。先把框裁剪到图像边界，再令 `cx=xmin+width//2, cy=ymin+height//2`。检测框必须完全位于图像内。像素坐标不是场地坐标，也不是毫米距离；框尺寸可辅助关联，但不能直接保证距离准确。

| type | 类型 |
|---:|---|
| 0 | 未知物体 |
| 1 | 绿色普通物资 |
| 2 | 黑色核心物资 |
| 3 | 橘色伤员 |
| 4 | 浅蓝危险物块 |
| 5 | 红方安全区整体，分区未知 |
| 6 | 蓝方安全区整体，分区未知 |
| 7 | 洋红出发区 |
| 8 | 障碍物 |
| 9 | 对方/其他机器人 |
| 10 | 红方安全区：物资放置区 |
| 11 | 红方安全区：伤员放置区 |
| 12 | 蓝方安全区：物资放置区 |
| 13 | 蓝方安全区：伤员放置区 |

分区沿用同一个检测条目结构，`cx、cy、width、height` 对应该分区自身的像素检测框，不是整个安全区的框。同帧看到多个分区时，分别作为独立条目上报。识别到分区后优先报告分区；仅识别到整体、无法确定分区时使用 5/6，不能默认当作物资区或伤员区。

新增 10～13 保留原有 0～9 的含义，版本仍为 v2，帧格式和长度不变。但旧版 STM32 校验会拒绝带新类型的整帧，部署时需同步更新单片机固件和相机端编码器。

相机必须实际识别出分区，不能仅凭红蓝颜色或画面左右位置推断其用途。YOLO 的类别编号须显式映射到协议类型，不能直接假定二者相同；如果现有模型只识别整个安全区，仍需补充分区标注训练或可靠的几何/标识识别。协议支持这些类型不代表分区识别算法已实现。

STM32 根据赛前配置的本队颜色选择目的地：普通/核心物资送本队物资区，伤员单独送本队伤员区，首次必须恰好 1 个普通物资送达本队物资区。5/6 不能作为已确认的投放分区；对方安全区及其分区不能作为本队目的地。检测框中心不是已验证的推送落点，实际导航、围栏内侧判断和送达确认仍待实现。

### 可选扩展检测列表 `CMD=11`

前14字节与0x10图像头相同，偏移14追加 `source_age_ms:uint16`，图像头共16字节。该值为相机自身单调时钟测得的“采集到准备发送”的耗时，单位毫秒，范围0～65535；超过范围或过期应丢弃结果，不得饱和后伪装为新鲜图像。

每个条目前10字节与0x10相同，条目内偏移10追加 `track_id:uint16`，每项共12字节。第i项从 `16+12*i` 开始。0表示未提供身份，非零ID须来自真实跟踪器，同帧不得重复，同一view_id内不得复用给另一目标。列表下标和按x排序编号都不能代替跟踪ID。0x10解码后的ID及耗时元数据均清零。

0x11最多19项，载荷最大244字节、整帧254字节。超过19项必须显式选取保留项并标截断，保留优先级沿用上文；不能默默丢掉危险物、障碍或其它实体。截断帧不用于判空、跟随或批准落框。

## 3. 相同物块如何区分

同帧使用列表下标即可。例如：

```text
frame_id=100, view_id=7, image=640x480
objects[0] = 普通物资，中心(120,300)，框40x40，置信度95
objects[1] = 普通物资，中心(420,310)，框38x38，置信度92
```

两块类型相同，但位置不同。下一帧检测器可能把顺序交换，所以不能把 `objects[0]` 永久理解为同一物块，也不能把“从左到右编号”当作跨帧身份。

相机可继续只发0x10，由STM32保留上一帧中心和框尺寸，进行同类型中心距离及尺寸门限匹配；也可用0x11提供真实track_id。锁定非零ID后只接受同ID，并继续检查类型、位置和尺寸，不回退匹配另一ID。仓库只有协议编码器，没有香橙派YOLO主程序或实际跟踪器，不能据此认为相机端跟踪已实现。未来若增加多目标同时关联，应采用一对一匹配，不能让两条轨迹同时占用同一个检测。

原目标未匹配、低置信或关联有歧义时立即停车，保留原锁定，连续3张有效新图均未匹配才判丢失；重复帧不累计。期间找回则清零丢失计数、复位PID，恢复帧仍停车，下一新帧继续原阶段；已前进的不重新原地对准。等待达到600 ms也结束，图像失效/过期、视角或尺寸改变等仍立即结束。计数及等待上限均有宏，找回不延长阶段及整轮计时。

相近物块遮挡、交叉或大幅位移可能导致关联不确定；相机重启/跟踪器重置必须使当前跟踪终止，例如在新视角握手前发送无效图像，不得沿用原view_id重新分配旧ID。最近邻和跟踪ID都不能保证外观完全相同物块交叉后的物理身份，全场稳定身份识别不由本协议保证。

初版关联不能保证相同物块遮挡、交叉后的身份。任务状态机位于`App_Task/App_Task.c`，目标选择、锁定及接近函数封装在同目录`app_task_vision.c`，具体流程、标定参数和待实现动作见 `App_Task/README.md`；协议模块只提供完整检测快照。

## 4. 摄像头转动与视角编号

STM32 控制摄像头舵机，不能只依据画面中的左右位置判断物块相对车身的左右。

1. 本地业务层进入扫描/转动状态，暂停使用原视角坐标进行接近。
2. 转动舵机，等待机构稳定。
3. 分配新的非零 view_id，并调用 `Rescue_Usart2_SendViewContext(view_id, yaw)`。yaw 为相对车头的目标偏角，单位 0.1°，正值向左，范围 -1800～1800；不是驱动中 0～180° 的绝对舵机角，需按安装方式标定转换。
4. 相机收到上下文后，只对随后采集的新图像锁存该 view_id；必须清除或识别驱动中的旧缓存图像。推理线程保留每幅图像采集时的编号，不得在发送时使用“最新全局编号”。
5. STM32 只使用 `scene.view_id == expected_view_id` 的图像。若上下文丢失，可重发相同上下文，直到图像回显匹配编号。编号回显不证明机械舵机实际角度；机构稳定等待仍由 STM32 实现。

车体本身大幅转动后也可以更新 view_id，使旧图像与新车身姿态区分开。启动固定视角时可使用 view_id=0；扫描业务应使用上述非零编号流程。

## 5. STM32 接口与时效

| 接口 | 用途 |
|---|---|
| `Rescue_Usart2_Start()` | USART2 初始化后启动单字节中断接收 |
| `Rescue_Usart2_RxCallback()` | HAL 接收回调中组帧并入队，不执行动作 |
| `Rescue_Usart2_Process()` | 主循环更新最新场景，无 ACK、无执行器副作用 |
| `Rescue_Usart2_GetScene(&scene)` | 主循环获取有效且接收年龄小于 500 ms 的完整场景，成功返回 1 |
| `Rescue_Usart2_LinkOnline()` | 判断近期是否收到有效心跳/检测消息，不等于图像新鲜 |
| `Rescue_Usart2_SendViewContext(id, yaw)` | 通知相机当前视角；成功发送返回 1 |
| `Rescue_Usart2_SendFrame(&frame)` | 通用发送接口 |
| `Rescue_Usart2_DroppedCount()` | 接收队列溢出计数 |
| `Rescue_Usart2_ParseErrorCount()` | 版本、长度、CRC、帧尾错误计数 |
| `Rescue_Usart2_BadDataCount()` | 检测载荷不合法、未知/反方向消息计数 |

`GetScene()` 返回 0 时不写输出变量，调用者不能继续使用变量中遗留的坐标。图像无效消息立刻覆盖旧场景。有效空列表也覆盖旧目标。错误载荷不会覆盖最近一次有效场景，原场景仍按原接收时间超时。重复图像不会延长其有效期；心跳也不会延长图像有效期。

接收时间在 ISR 收完帧时记录，主循环排队延迟不会刷新它。500 ms 是当前接收年龄上限，由头文件 `RESCUE_VISION_TIMEOUT_MS` 配置；业务层应结合速度、检测帧率设置更严格的追踪年龄。`capture_ms` 与 STM32 时钟未同步，禁止直接用 `HAL_GetTick()-capture_ms` 判断年龄。接收年龄不能检测相机内部积压，因此相机须保留最新图像、限制推理和发送延迟，不得重复上报缓存结果冒充新采集。

当前任务要求本地收帧年龄小于200 ms；0x11还要求 `source_age_ms + ceil(帧字节数×10000/115200) + 本地收帧年龄 < 300 ms`，其中串口按115200/8N1估算。参数在app_task_config.h。此算法不需要两端时钟同步，但不能测出编码后等待、串口隐藏排队及摄像头驱动缓存；相机须在发送前计算耗时并立即发送。0x10没有采集至发送耗时，仍只能检查本地年龄。

调用示意（业务函数为占位名称，不是已实现 API）：

```c
static RescueScene scene;
Rescue_Usart2_Process();
if (Rescue_Usart2_GetScene(&scene) && scene.view_id == expected_view_id) {
    /* 本地状态机：选目标/关联/转向/接近；图像身份
     * (frame_id, capture_ms, view_id) 改变时才更新跟踪器。 */
} else {
    /* 接近状态撤销旧坐标并停车，或转入重新扫描状态。 */
}
/* 本地状态机必须持续调用当前动作所需的 App_Speed_Pro()
 * 或 App_Angle_Pro()；USART2_Process 不再替业务层运行闭环。 */
```

固件上电后等待启动按键，`main.c` 的 KEY2 选蓝方并启动、KEY3 选红方并启动，同时按下优先红方；KEY1仅调试打印，不启动任务。按下后，`App_Task` 以20 cm/s直行宏 `APP_TASK_FORWARD_TIME_MS` 指定的时间，再原地右转检测；没有合适绿色目标时转到另一侧再检测。落框首运只选择type=1；需要撞散时可瞄准物资堆中靠近画面中心x的普通/核心物资，但不允许提前转运核心物资入区。其它物块、区域、障碍和对方车参与检查。全部任务执行参数（含视觉PID、速度、死区、屏幕中心与中心Y门限）集中在`App_Task/app_task_config.h`。运行中不切队，重试不重置整轮3分钟计时；落框后异常不接受按键重启，需人工处理后复位。

找到绿色后先锁定、原地对准一次，再以基础速度加减视觉PID输出持续前进，前进后不返回原地对准。远处死区10/20 px，距停车门限40 px内使用4/8 px，避免最终±10 px的落框要求与死区冲突。单独性间隔取固定像素与检测框尺寸比例中的较大值，近处判断更保守；参数均可调。搜索连续3张有效新图没候选才判本侧空，同帧不重复计数。

像素归一化到640×480：单独绿色默认中心cy≥400且横向误差≤10 px时先停车，至少150 ms且至少3张新图位置稳定（相对首张x/y漂移≤6 px）才落前框、摄像头低头至45°；停车期间cy回落≤3 px仍保持复核，回落更大则清零恢复接近，横向超限则结束。机械稳定后更新view_id，要求前框图像区域内连续3张新图恰好一个完整且可信绿色。框外物块不计数、区域标签不计作实体；列表截断/无效/过期/旧视角不能批准复检。相机仍发送完整检测列表，由STM32按可调区域判断，无需新增框内数量字段。二维图像不能保证实际框内数量，区域须实测标定。

无单独绿色时，物资堆默认目标cy≥400且横向对准、停车多帧复核后，额外编码器前推5 cm、顺时针原地旋转1秒（单轮5 cm/s），再换view_id重选；撞散动作封装在`app_task_scatter.c`，参数可调。可见普通/核心物资总数超过3、低置信物资或出现伤员/危险/机器人/未知物/区域等禁碰类型则拒绝撞散；动作中持续检查新鲜完整场景，接触后不再关联被推动的旧目标。

复检通过后恢复摄像头75°、编码器后退、更新view_id，再原地寻找本队物资分区（红方type10、蓝方type12）。整体安全区5/6、伤员分区及对方物资分区不作目的地；找到后首次对准、视觉PID差速接近，默认分区中心cy≥360且横向对准、停车多帧复核后抬框，再编码器后退，前框保持抬起，进入空的新循环接口。停车门限均为像素，并非厘米或围栏内有效送达证明；未解锁其它救援目标，尚无有效送达确认和完整避障。

相机须回显view_id，搜索/分离后及摄像头俯角切换后丢弃旧视角；上下俯角不是水平yaw，当前发送yaw=0，用新view_id区分。连续视觉对准/接近保留编号，依赖新帧关联，接收年龄收紧为200 ms；同帧不重复运行PID或累计复检次数。仅发送心跳无法完成检测。

## 6. 相机端参考编码与联调

同目录 `vision_protocol.py` 提供纯 Python 标准库编码器和串口字节流解析器，可嵌入香橙派程序。它不是检测模型，也不会控制摄像头或舵机。

```python
from vision_protocol import Detection, encode_scene

# view_id/capture_ms 必须在采集图像时保存，不能在推理完成时才取。
packet = encode_scene(
    sequence=1, frame_id=100, capture_ms=123456, view_id=7,
    image_width=640, image_height=480,
    objects=[Detection(1, 95, 120, 300, 40, 40),
             Detection(1, 92, 420, 310, 38, 38)],
)
serial_port.write(packet)
```

启用0x11时，在真正写串口之前调用以下接口；`capture_ms`须在采集时由同一个单调时钟保存，`tracker_id`来自真实跟踪器：

```python
from vision_protocol import encode_latest_scene

# 采集时保存：capture_ms = (time.monotonic_ns() // 1_000_000) & 0xffffffff
# 推理、真实跟踪及坐标还原完成后，发送前编码；过期会抛ValueError，应丢弃该结果。
packet = encode_latest_scene(
    sequence=1, frame_id=100, capture_ms=capture_ms, max_age_ms=250,
    view_id=7, image_width=640, image_height=480,
    objects=[Detection(1, 95, 320, 300, 40, 40, track_id=tracker_id)],
)
serial_port.write(packet)
```

250 ms只是相机侧示例上限，STM32仍会加上传输及本地等待检查300 ms上限。未接跟踪器可将ID设0，仍能使用耗时检查。也可对`encode_scene()`显式传`source_age_ms`选择0x11，但调用者必须保证耗时正确。此辅助函数不会管理采集队列、运行YOLO或实现跟踪；相机须另行接入“只保留最新待推理图、丢弃旧结果”的处理，并避免编码后排队。跟踪器重启时按上文终止旧锁定。

例如同帧检测到红方两个分区时，可使用下面的 `objects` 列表（坐标仅为编码示例，不表示固定场地布局）：

```python
from vision_protocol import OBJECT_RED_SUPPLY_ZONE, OBJECT_RED_CASUALTY_ZONE

objects = [
    Detection(OBJECT_RED_SUPPLY_ZONE, 95, 160, 120, 160, 80),
    Detection(OBJECT_RED_CASUALTY_ZONE, 93, 400, 120, 160, 80),
]
# 将 objects 传入上面的 encode_scene()，蓝方对应类型为 12、13。
```

建议新图像以 10～20 Hz 上报。0x10的20项整帧224字节，115200/8N1占线约19.4 ms，20 Hz占TX带宽约39%；0x11的19项整帧254字节，占线约22.1 ms，20 Hz约44%。图像流正常时无需额外心跳；无新图像时可发心跳，但图像处理故障应主动发送无效图像消息。
