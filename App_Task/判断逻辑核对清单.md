## 各阶段对同一“读图失败”的处理不同

| 阶段 | 任一C组读图条件失败时的行为 |
|---|---|
| 两侧检测/撞散重选 | 等待，清判空次数；检测时限仍继续 |
| 对准/接近 | 一次读取失败就立即scene_invalid退出；不是等3张坏图 |
| 框内复检 | 清张数和合格数继续等；3秒总时限不延长 |
| 后退 | 不调用视觉检查；按编码器和整轮时间判断 |
| 原地搜索物资区 | 第一张合格图之前等待；已经收过合格图以后读图失败立即退出 |
| 撞散推动/旋转 | 一次失败立即终止 |

## 容易形成长时间停车的组合

1. F10的纵向滞回区可以既不运动也不到位，最终由E14接近15秒超时结束。
2. 落框接受y=390～410，G06复检接受y=400～450；摄像头仍固定50°。若目标落框后还停在390～399，可能连续三张都不合格，触发G11失败。应结合落框后的实际坐标判断。
3. G07～G09的冲突立即失败优先于“三张至少一张合格”，一张合格不会覆盖另一张多件/非绿色/低置信冲突。
4. C02的100 ms重发若失败，会清view_sent；即使缓存图像其它字段合格，对准/接近仍可能scene_invalid。
5. A08落框锁使“已经停车后再按键不走”成为确定的软件行为；N09使“完成一趟后不再出发”成为当前空接口行为。
