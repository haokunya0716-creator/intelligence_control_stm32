# 小车运行流程

更新日期：2026-10-23。本文描述正式救援任务流程；每次修改任务逻辑同步更新本文。比赛规则见 [RULES.md](RULES.md)。

## 当前运行模式

临时视觉跟踪测试代码已删除，工程现在始终执行正式任务状态机。KEY2选择蓝方并启动，KEY3选择红方并启动；KEY1不启动任务。当前用于初步调试，执行启动直行、顺时针旋转搜索、绿色目标跟踪、前框落下复检、寻找本队物资放置区和后退释放；所有物块相邻判断已移除，依赖相邻关系的自动撞散暂不触发。

正式启动后，先以20 cm/s速度直行`APP_TASK_FORWARD_TIME_MS`，随后立即按左轮+15、右轮-15 cm/s持续原地顺时针旋转，边转边搜索绿色物资。启动搜索与寻找本队物资区共用`APP_TASK_ZONE_SPIN_SPEED`，不再先右转90°再换向180°。搜索只按目标自身type=1及置信度≥70%选择绿色，不检查周围框的间隙、类别或数量来判断是否相邻；多个绿色沿用框底边更低优先、同底边时更靠近瞄准中心x的排序。锁定后停车，执行一次原地横向对准，随后使用视觉PID差速持续前进；目标中心Y达到停车门限后进行多帧稳定复核。

测试版与正式版的单目标跟踪核心（目标关联、横向PID、差速前进、Y停车门限）使用了相近思路，但整体行为不一致：测试版只在当前视野持续找绿色并打印丢失/恢复日志，不执行启动旋转搜索、撞散、落框、固定角度复检、转运和安全区搜索；正式版按比赛规则执行完整状态机，普通物块丢失仍按连续新帧及超时判定失败，安全区失配则立即旋转重搜。测试版的`line_test_kp`、`line_test_ki`、`line_test_dx`在线调参变量随测试文件一并删除，正式参数统一来自`app_task_config.h`和`App_LinePID`。

`app_line_test.c/.h`已从工程和CMake源文件列表移除；`APP_LINE_TEST_ENABLE`及测试专用积分分离宏也已删除。后续按键不会再进入测试跟踪入口。本文后面的正式流程是当前实际固件流程，历史记录中的测试描述仅用于追溯。
## 正式任务流程

已撤销串口字符`1`切换前框的临时功能。串口2恢复接收视觉协议，按KEY2选择蓝方启动、KEY3选择红方启动；裸字符`1`不触发舵机。

```text
上电，停车等待
    ↓ KEY2：选择蓝方并启动；KEY3：选择红方并启动（KEY1仅调试打印）
首次启动开始整轮 3 分钟计时，重试不重置
    ↓
前框抬起 SERVO1_LIFT=180°，摄像头 SERVO2_LIFT=50°，速度闭环以 20 cm/s 直行 2 秒
    ↓
立即发送新的非零view_id，左轮+15、右轮-15 cm/s原地顺时针旋转（与物资区搜索共用轮速宏）
    ↓ 不等待200 ms，不执行固定角度转向；边旋转边检测
读取完整、有效、当前视角图像，选择置信度≥70%的绿色，不再检查相邻物块或区域框
    ├─ 找到 → 锁定并停车，进入下方对准/接近流程
    ├─ 没找到（包括连续3张空图）→ 继续顺时针旋转，不按原每侧2秒结束搜索
    └─ 无图/旧视角/图像过期或无效/列表截断 → 不选目标，继续旋转等新图；整轮3分钟到时仍停车

锁定同一个物块 → TASK_FOLLOW（对准和接近由视觉函数内部执行）
    ↓ 以锁定帧的位置、尺寸和可选track_id关联同一目标；不因框贴画面边缘退出
首次原地对准：目标中心x进入中心±10 px
    ↓ 到位停车，复位视觉PID
单独绿色 → 与临时跟踪测试相同的XY跟随控制
    ├─ X轴：沿用已调好的视觉PID，行驶中差速纠偏
    ├─ Y轴：P控制前进/倒车，Kp=0.12；最小调整3 cm/s，前进上限25 cm/s、倒车上限3 cm/s
    ├─ y进入412～432 px：纵向停车；x偏离时只进行横向PID修正
    ├─ 误差越过±20 px外门限、停车满200 ms且连续3张新图方向一致 → 才开始/恢复前后运动
    └─ x、y到位且连续3张稳定新图、停车≥150 ms → 进入落框、复检流程
绿色旁边新增普通/核心物资、安全区或其它检测框 → 不因相邻而退出，继续关联原目标
    ↓ 不再按拥挤情况自动进入撞散；撞散动作和状态接口仅保留，当前选目标不会触发
物资区 → 继续原分区对准、接近及失配旋转重搜流程

目标中心已达到停车门限且x已在允许范围 → 停车复核
    ├─ 已到Y门限但x偏差>10 px → 暂停平移，只用PID转向，禁止继续前进
    └─ x进入允许范围 → 到位动作不是单帧触发
至少停车150 ms，至少连续3张新图均在允许区域且相对首张位置漂移≤6 px
    ├─ 单独绿色y仍在412～432；物资堆/分区y仅回落≤3 px → 保持停车复核
    ├─ 单独绿色y＜412，或物资堆/分区y回落超过3 px → 清空到位计数，恢复接近
    └─ 未满足到位条件 → 不落框；绿色继续原XY调整，物资区沿用原通道判断及失配重搜
任何步骤整轮达到 3 分钟 → 停车，本轮不再响应启动按键
```

## 文件分工

| 文件 | 负责内容 |
|---|---|
| `App_Task.c/.h` | 对外启动/周期调用接口；任务步骤、状态切换、整轮计时及载物锁 |
| `app_task_config.h` | 全部任务行为宏：启动、舵机、图像、PID、复检、行程、安全区、撞散；每项有注释 |
| `app_task_vision.c/.h` | 选目标、跨帧关联、视角更新、首次对准和PID差速接近、框内复检、搜索本队物资区 |
| `app_task_zone.c/.h` | 按同帧整体安全区5/6与分界线14计算左物资、右伤员；独立保存本地分区，不覆盖原始检测 |
| `app_task_move.c/.h` | 停车、速度闭环、角度转向、编码器正/负距离移动、前框/相机动作、新循环空接口 |
| `app_task_scatter.c/.h` | `Start()`开始额外前推，`Proc()`非阻塞执行前推→旋转→停车并返回结果 |
| `User_gx/App_LinePID/app_line_pid.c/.h` | 保留原PID计算、复位和死区函数，行为参数统一引用`app_task_config.h` |

`App_Task_Vision_Follow()`封装“首次对准一次→持续向前PID纠偏”，单独绿色、物资堆与本队物资区共用。`App_Task.c`只根据函数结果安排下一步，不直接操作电机、相机串口或计算PID。底层轮速/角度PID仍由原来的`app_speed`和`app_motor`维护。

## 串口1任务日志与接收超时

串口1设置115200、8N1，文本接收；STM32 PA9为TX，连接USB转串口模块RX并共地。已删除周期相机摘要；当前打印任务/转向事件、全部任务失败/超时/拒启动原因，以及失败时的视觉/编码器现场。`[SCENE]`仅用于事件诊断，不恢复周期相机摘要。

```text
相机向串口2发送数据 → 正常解析并更新场景，不打印相机内容
    ↓
任务状态切换 / 转向开始、到位、超时 → 串口1打印对应日志
连续10秒没收到任何字节 → uart_error（本次断流只打印一次）
    ↓ 收到任意字节（包括乱码、解析失败的数据）
重新计时，再次连续断流10秒才重新报告
```

`uart_error`只用于提示，不直接改变任务或舵机动作。

任务诊断默认开启（`APP_TASK_DEBUG_ENABLE=1`），同样使用串口1。当前状态编号：0停车、1启动直行、4顺时针旋转搜索、6撞散后重选、7对准/接近、8撞散、9等待落框、11框内复检、14物资区搜索、15物资区接近、16等待抬框、17卸下后退离、18新循环预留。保留后续状态编号，删除启动固定转向2/3、另一侧检测5及复检后退13。正常顺序示例如下：

```text
[TASK] state=1       → 启动直行2秒
[TASK] state=4       → 持续顺时针旋转寻找绿色
[TASK] state=7       → 找到目标并停车，进入共用对准/接近流程
[TASK] state=9       → 单独绿色到位，落框等待500 ms
[TASK] state=11      → 立即读取三张新图复检
[TASK] state=14      → 通过后直接寻找物资区，没有后退13
[TASK] state=15      → 物资区锁定，开始对准/接近
```

启动旋转搜索不再调用固定角度转向接口，因此不再产生该段`[TURN]`日志，也不受该接口5秒转向超时限制。日志只在状态切换/动作事件打印，不按控制周期连续打印。

任务失败、超时和拒启动均打印明确原因；失败动作先撤销运动，随后输出诊断。安全区仍按原规则在同次调用内旋转重搜，再打印重搜原因。正常等待不等同任务失败，同一种持续等待只在首次出现或原因变化时提示，重复帧不会按主循环周期刷屏。

```text
任务中的原有判断未通过
    ↓ 动作层打印具体原因和现场数值
[VERIFY] stop=cargo_low_confidence
[SCENE] reason=ok snapshot=1 frame=100 age=10
[SCENE] view=2/2 flags=1 n=1 img=(1280,720)
[VERIFY] frames=0/3 hits=0/1 wait=cargo_low_confidence
[VERIFY] new=1 duplicate=0 invalid=0 cargo=cargo_low_confidence count=1 idx=0
[VERIFY] region=(230..490,400..450) ref=(640,480)
[VERIFY] obj=0 type=1 conf=60 xy=(360.0,422.0) in=1 entity=1
    ↓ 任务层打印失败步骤与耗时，示例数值仅说明格式
[TASK] stop=verify_failed state=11 dt=100 round=4000
[TASK] state=0
```

`[TASK] stop`是任务退出汇总，`state`保留失败前的步骤编号，`dt`为步骤耗时、`round`为整轮耗时，单位ms。应同时查看前面的动作层具体原因。例如`verify_failed`需要对应`[VERIFY] stop`；`follow_failed`对应`[FOLLOW] stop`及`[SCENE] reason`/`[MATCH] reason`；`release_back_failed`对应`[MOVE] stop`。

| 位置 | 完整原因及含义 |
|---|---|
| TASK退出 | `round_timeout`整轮180秒；`reselect_timeout`撞散重选2秒超时；`reselect_empty`连续有效新图无绿色；`verify_timeout`框内复检3秒超时 |
| TASK子动作退出 | `follow_failed`物块跟随；`verify_failed`复检；`scatter_failed`撞散；`zone_search_failed`物资区搜索失败返回；`zone_follow_failed`物资区跟随失败返回；`release_back_failed`卸下后退离失败返回。安全区正常失配仍重搜，不转空闲 |
| TASK拒启动 | `busy`运行中；`cargo_pending`载物锁；`invalid_team`队伍参数非法；`round_timeout`整轮已经到时 |
| VERIFY立即失败 | `cargo_multiple`复检区域内多个实体；`cargo_wrong_type`非绿色；`cargo_low_confidence`绿色置信度不足 |
| VERIFY窗口失败 | `no_hit_in_window`收齐3张无冲突有效新图但无合格帧；超时由TASK打印`verify_timeout`，同时打印最后等待原因及累计情况 |
| SCENE读图 | `view_not_sent`尚未到发送时刻；`view_send_failed`视角命令发送未成功；`scene_unavailable`接收接口未提供可用场景；`view_mismatch`图像view_id与当前阶段不符 |
| SCENE有效性 | `image_invalid`有效标志未置位；`list_truncated`列表截断；`receive_age`本地接收年龄超限；`source_age`扩展帧合计年龄超限；`camera_angle`摄像头设定角与阶段期望不符 |
| SELECT等待 | `no_green`当前无绿色候选；`green_low_confidence`绿色自身置信度不足；`duplicate_frame`只有重复帧，在重选超时现场中显示；其它wait原因来自SCENE |
| MATCH关联 | `no_same_type`无同类别目标；`candidates_rejected`候选被置信度、ID、宽、高或位移条件排除；`ambiguous`最近/次近候选得分无法区分；`image_size_changed`分辨率改变 |
| FOLLOW阶段 | `align_timeout`首次对准超时；`approach_timeout`接近超时；`scene_invalid`读图未通过，具体看SCENE；`target_lost`连续3张未匹配；`lost_timeout`等待超过600ms；`image_size_changed`分辨率改变；`arrive_off_center`到位横向超限，另打印ARRIVE实际x、目标x、容差和y |
| MOVE编码器 | `invalid_speed`速度参数≤0；`move_timeout`直线运动超时；`left_reverse`/`right_reverse`对应轮反向超限；`wheel_skew`两轮行程差超限。附方向、速度、耗时、两轮行程、目标距离及差值 |
| TURN角度接口 | `turn_timeout`角度转向超时，打印实际航向和目标航向；当前启动不调用固定角度转向 |
| SCATTER拒启动 | `invalid_push_distance`/`invalid_push_speed`/`invalid_spin_speed`/`invalid_spin_time`对应参数无效；`vision_check`见SCATTER detail |
| SCATTER执行失败 | `not_started`未成功启动；`scatter_timeout`总时限；`push_failed`前推编码器失败，细节见MOVE；`vision_check`视觉检查未通过。跟随时`scatter_unsafe`也附同一套SCATTER detail |
| SCATTER detail | `camera_mode`期望俯角不是正常角；`image_size_changed`分辨率改变；`frame_not_lifted`前框设定角不是抬起角；`forbidden_type`禁碰类型；`low_confidence`物资置信度不足；`too_many_supplies`超过数量；其它原因来自SCENE。附实际触发对象下标、类型、置信度和坐标 |
| ZONE候选 | `zone_multiple`多个同类本队分区；`zone_low_confidence`本队分区低置信；`zone_ambiguous`分区确认与关联不一致，细节看ZONE detail；`zone_path_blocked`物资区通道阻挡，附真正阻挡框 |
| ZONE推导等待 | `divider_missing`/`divider_multiple`/`divider_invalid_box`/`divider_low_confidence`分别为分界线缺失、多条、框坐标不合法、低置信；`whole_zone_missing`/`whole_zone_multiple`/`whole_zone_invalid_box`/`whole_zone_low_confidence`为整体区相应原因 |
| ZONE其它推导 | `only_casualty_zone`仅有直接伤员分区导致沿用直接标签而没有物资分区；`supply_empty_after_clip`物资区交集宽高为空；`invalid_zone_input`推导输入不合法。均沿用原推导结果，不新增几何门限 |
| ZONE重搜 | `[ZONE] research=原因`沿用跟随原因；`target_missing`表示未关联到分区，具体ID/位置/尺寸原因看MATCH。立即旋转重搜，原view_id、载物锁及180秒整轮计时不重置 |

`[SCENE] snapshot=1`表示本次取得了接收快照，仍可能视角、标志或年龄不合格；`snapshot=0`时后面的图像字段只是上次保存值。时效失败另打印检查年龄及门限，摄像头角度失败另打印实际设定角、期望角和容差。

`[MATCH] reject(type,conf,id,w,h,dist)`按原筛选顺序，分别累计每个候选首先不满足的条件；`best2`/`second2`是最近/次近候选的平方距离。`[TRACK]`保存本次跟随判断前的关联参考框（安全区重搜会在清理前保存失败时的目标）；原有`[TARGET]`仍是失败位置当时保存的目标。`not_checked`表示本次尚未执行该子检查，不能当作失败原因。

`[VERIFY] frames/hits`是当前复检窗口的无冲突新图数量/合格数量；`new`是本阶段有效新图总数（包括冲突图），`duplicate`为重复帧调用次数，`invalid`为读图失败调用次数。无效图仍按原规则清空当前窗口。失败/超时会打印最后保存图像的每个对象：`xy`统一为640×480中心坐标，`in`表示中心在复检区域内，`entity`表示此类别是否计作物块；安全区、分区等背景标签`entity=0`。

本次仅增加诊断记录和打印，继续使用`APP_TASK_DEBUG_ENABLE=1`与串口1的115200/8N1；设0关闭诊断，不改变判断结果。此前删除的物块相邻检查、`path_blocked`/`target_crowded`出口及邻居打印保持已删除。正常框内复检、目标跟踪、XY控制、安全区重搜和动作门限沿用当前代码。

接收超时开关`RESCUE_DEBUG_ENABLE`、断流门限`RESCUE_RX_TIMEOUT_MS=10000`位于`rescue_usart2.h`；上电从串口2开始接收时计时，开关设0只关闭`uart_error`，不影响视觉接收和任务日志。任务/转向日志仍由`APP_TASK_DEBUG_ENABLE`控制。日志复用现有`App_USART1_Printf()`，只在主循环中发送。

## 落框、复检与首运

```text
单独绿色接近到停车门限、横向已对准且停车多帧复核通过
    ↓ 停车，锁住按键重启入口
一号舵机 SERVO1_DROP=75°，前框落下，等待500 ms
    ↓ 摄像头保持50°，取消低头/抬起动作及两次500 ms等待
立即发送新view_id，排除落框前旧图，不再等待画面稳定200 ms
    ↓ 收集3张完整、有效、当前视角的新图；重复帧不计数
按物块中心坐标复检：230≤x≤490、400≤y≤450（含端点，按640×480换算，与标定测试打印的x/y一致）
    ├─ 中心在区域外 → 忽略；检测框边缘不参与前框区域判断
    ├─ 单张区域内恰好1个绿色中心、置信度≥70% → 记为1次合格；空区域也占1张
    ├─ 收齐3张新图，其中至少1张合格 → 通过；第一张合格也先收齐3张
    ├─ 收齐3张新图，全部不合格 → 立即停车结束，不再等满3秒
```

同帧重复调用不累计复检次数；中心在区域外的实体不计数，区域标签不作为实体计数。位置判断仅使用中心x=cx×640/image_width、y=cy×480/image_height，与`app_cargo_test.h`的打印值一致；不要求检测框完整入区，也不按框相交计数。中心入区只能作为图像复检依据，不能证明机械包围或被遮挡物数量。摄像头在复检前后保持50°，不发送切角度动作；500 ms机械等待仅保留在前框落下和抬起之后，没有机械到位反馈。启动旋转搜索、复检和物资区搜索均无200 ms固定稳定等待；撞散重选仍保留200 ms。

安全区搜索不设固定等待或单独15秒结束条件：无图、图像过期/无效/截断、视角不符、低置信或候选不唯一时仍继续旋转，只有完整有效的新图能锁定。每次新图找到唯一可信本队物资区就立即锁定，不做3帧位置稳定确认。对准/接近期间，一旦匹配失败（含类型、ID、位移或尺寸不匹配）、图像失效/过期、分辨率变化、分区歧义、通道阻挡、对准/接近超时或到位复核横向不合格，立即撤销前进并在同一次调用下发旋转轮速，返回RESEARCH，由任务状态机直接切回搜索；不再等待3张丢失帧、600 ms或按键重启。重新锁定后重新执行原视觉PID首次对准，再前进。

每帧重新用本帧整体区和分界线计算分区，不复用上一帧的线；重搜时相机保持50°，沿用当前view_id和已处理帧记录，不触发换视角握手或固定等待，也不把已经处理过的失配帧重新当新帧。原始检测、数量和图像耗时保持原输入，本地最多4个分区单独保存，track_id=0，不靠跨帧ID保持分区身份；相机直接上报非零ID仍按原匹配要求检查，但不匹配只重搜。伤员分区仍只提供位置并参与原通道检查，伤员转运未实现。首次原地对准时本队伤员区和已关联分界线按原例外处理，前进后恢复通道检查；轮速沿用当前共享宏15 cm/s，重搜不重置180秒整轮计时、载物标志或前框角度。

按用户要求，已删除分区计算开关、贴边余量、最小宽高、整体宽高比、线在区内、横纵居中、线宽/线高/线形状及共享其它区域拒绝判断；同一条线可以用于红蓝区各自计算，不再按这些条件拒绝。仍保留类型标记、同帧数量、置信度≥70%、坐标框合法性及相机直接分区兼容；同帧多条type14时不任意挑选，继续搜索。整体框按原660×360 mm外框及单边30 mm围栏比例内缩；左右规则仍以图纸和入口正面为前提，未实现透视校正。360 px停车门限、抬框前150 ms/3帧到位复核和其它机械动作保持原值，实际分区及停车点待实车验证。

前往分区的图像通道会排除危险物、障碍、机器人、未知物、伤员、核心物资、对方区域及本队伤员区；允许一条绿色检测，因为前框内物块可能出现在画面里。这仍无法区分途中另一个绿色与框内绿色，也不能保证未识别/被遮挡目标的安全，尚未实现全局定位、完整避障及转运途中持续载物确认。

**像素中心到达不等于进入围栏，抬框也不等于确认得分。** 本版实现请求的首运动作顺序，尚未实现围栏内有效送达确认；新循环接口保持空白，不设置首运成功、不解锁核心物资/伤员。应实车标定停车门限，使物块真正进入本队物资区围栏内侧，并补充送达确认后再接新循环。

启动和物资区旋转搜索均直接设置左右轮速，只运行速度内环；视觉首次对准和接近继续使用原视觉PID。`APP_TASK_ZONE_SPIN_SPEED=15.0f`表示单轮线速度15 cm/s，左轮取正、右轮取负时顺时针旋转，不表示5°/s。修改这一个宏后重新编译，两处搜索速度同步变化。

原固定角度转向接口、连续剩余角度算法及其±3°/最小5 cm/s/5秒超时参数保留，当前启动流程不调用。`APP_TASK_RIGHT_ANGLE`和`APP_TASK_LEFT_ANGLE`仅保留旧参数，不再控制启动路线；不影响原底盘其它角度控制接口。

启动找绿色和物资区搜索均无单独搜索超时，没找到就继续转，直到找到有效目标或整轮到时。撞散后的静止重选仍保持200 ms稳定等待、连续3张有效新图无候选或2秒超时停车；普通物块跟随仍保留原3张丢失/600 ms处理。

## 首次对准与前进纠偏

```text
横向误差 = 目标中心 x - LINE_PID_AIM_X
    ├─ 首次原地对准：左轮=修正量，右轮=-修正量
    │                  └─ 误差进入 ±10 px 后结束，只执行一次
    └─ 接近中：左轮=基础速度+修正量，右轮=基础速度-修正量
                   ├─ 目标偏右 → 左轮加速、右轮减速
                   ├─ 目标偏左 → 左轮减速、右轮加速
                   ├─ 远处：|误差|≤10 px关闭修正；＞10 px开启
                   ├─ 近处：|误差|≤10 px关闭修正；＞10 px开启
                   └─ 两门限之间 → 保持上一次修正开关状态

中心 y 距停车门限 >40 px → 基础速度25 cm/s
中心 y 距停车门限 ≤40 px → 基础速度15 cm/s
单独绿色390≤y≤410且x在±10 px内 → 停车，多帧复核后才允许落框
单独绿色Y误差超出±10 px → 按纵向Kp=0.12计算前进/倒车速度，最小调整3 cm/s，前进上限25 cm/s、倒车上限3 cm/s
首次启动或方向改变时先停车；误差须越过±20 px外门限，并满足停车至少250 ms、连续3张有效新图方向一致后才启动
单独绿色390≤y≤410且x在±10 px内 → 停车，多帧复核后才允许落框
单独绿色y在412～432但x超出±10 px → 速度设为0，仅PID转向；对准后停车复核

```

视觉 PID 放在 `User_gx/App_LinePID/`，绿色与物资区对准/接近共用，与 `app_speed` 一样使用 `PID_TypeDef` 和公共 PID 接口；当前 Kp=0.2、Ki=0、Kd=0。公共 PID 计算 SP-FB，视觉模块取反后使正修正量对应右转。死区内清空 PID 历史，避免恢复纠偏时带入旧积分。

修正量最多60 cm/s，平移时还限制为基础速度绝对值的80%，以两者中更小的值为准。因此快行差速最多20 cm/s、慢行最多12 cm/s；倒车修正差速最多4 cm/s，避免纠偏让任一侧电机反向。首次原地对准及已到Y门限后的横向修正将基础速度设为0，只执行转向。`LINE_PID_FORWARD_RATIO`应保持大于0、小于1；基础/慢行速度均应为正。正常接近时即使横向偏差超过70 px，也不会重新原地转向；相邻帧位置跳变超过跟踪门限仍会停车。

同一张图只更新一次目标匹配、死区和轮速设定；帧间持续调用速度闭环，图像接收年龄达到200 ms即停车。到位横向允许范围由独立宏`APP_TASK_ARRIVE_X`设置，默认±10 px。单独绿色的X/Y控制与临时测试版一致；正式流程继续保留目标关联、图像有效性、连续丢失停车和比赛任务状态约束，物块相邻/拥挤判断已经删除。物资堆和安全区不走单绿色Y轴控制。
